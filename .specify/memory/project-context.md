# AI_PRG: Единый контекст проекта

## 1. Назначение документа
Этот файл фиксирует стабильный контекст для SpecKit, чтобы агент не терял:
1. Общие продуктовые цели.
2. Архитектурные правила.
3. Технические ограничения.
4. Источники истины по требованиям и данным.

## 2. Продукт в одном абзаце
AI_PRG - кроссплатформенная нарративная RPG-платформа на Flutter, где AI генерирует историю и варианты последствий, а детерминированный движок валидирует и применяет только допустимые изменения состояния. Поддерживаются разные AI-провайдеры (включая LM Studio), краткая и длинная кампания, а также многослойная память для связности длинных сессий.

## 4. Инварианты домена (нельзя нарушать)
1. AI output недоверенный до валидации.
2. Состояние мира, инвентаря и квестов меняется только через движок.
3. Любой ход должен быть воспроизводим из `turn_log` + state snapshot.
4. Save/load обязаны быть обратно совместимы в пределах минорной версии схемы.

## 5. Технологический профиль (текущий)
1. Клиент: Flutter (desktop-first, затем mobile/web).
2. Lint/quality: `flutter_lints` + усиленные правила analyzer.
3. AI-layer: provider-agnostic gateway + адаптеры.
4. Локальный AI режим: LM Studio через OpenAI-compatible API.

## 6. Что обязательно держать синхронизированным
1. При изменении требований обновлять `PRD.md`.
2. При изменении модулей обновлять `Architecture.md`.
3. При изменении сущностей/контрактов обновлять `entities.models.json`.
4. При изменении инженерных правил обновлять `FlutterRules.md` и `analysis_options.yaml`.
5. При изменении базовых принципов обновлять `.specify/memory/constitution.md`.

## 8. Локализация как инвариант продукта
1. Приложение должно по умолчанию запускаться на русском языке.
2. Приложение обязано поддерживать два полных языковых состояния: `ru` и `en`.
3. Переключение языка должно менять весь пользовательский опыт целиком:
   - интерфейс, кнопки, заголовки и подписи;
   - статусы, ошибки и служебные сообщения;
   - стартовые игровые тексты и демо-ответы;
   - AI-промпты и ожидаемый язык ответа модели.
4. Для режима `ru` весь UI и весь AI-вывод должны быть на русском.
5. Для режима `en` весь UI и весь AI-вывод должны быть на английском.
6. Любая новая фича считается незавершенной, если она реализована только для одного из двух поддерживаемых языков.
