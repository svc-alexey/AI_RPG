## 2. Цель пользователя

Игрок narrative RPG хочет более глубокое погружение в историю: богатые описания сцен, эмоции персонажей, диалоги и атмосферу. Сейчас AI возвращает короткое продолжение сцены; пользователь ожидает более выразительное повествование без потери детерминизма и стабильности игры.

## 3. Пользовательские сценарии

1. **Богатая сцена** — Игрок выполняет действие (например, «осматриваю комнату»). AI возвращает описание с атмосферой, сенсорными деталями (свет, звук, запах) и кратким указанием на настроение места. Игрок чувствует присутствие в мире.

2. **Эмоциональный отклик** — Игрок взаимодействует с NPC (диалог, конфликт, союз). AI передаёт эмоции персонажей через короткие реплики и описания жестов/тона. Игрок понимает, как его действия влияют на отношения.

3. **Диалоги в потоке** — В narration появляются короткие прямые реплики персонажей («— Пойдём, — сказал стражник, хмурясь»). Текст остаётся в одном поле `narration`, но стилистически обогащён.

## 4. Функциональные требования

### 4.1 Расширение AI-промптов

1. System prompt должен содержать инструкции по narrative depth:
   - атмосфера сцены (настроение места, время суток, погода при уместности);
   - эмоции персонажей (тон, жесты, краткие реплики);
   - сенсорные детали (звук, свет, тактильность) в меру;
   - диалоги — короткие, в потоке narration, без избыточности.

2. Ограничения остаются: narration 1–2 абзаца для обычного режима, короче для fast mode.

3. Инструкции должны быть на обоих языках (ru/en) в зависимости от выбранного языка приложения.

### 4.2 Совместимость с существующим контрактом

1. JSON-контракт `narration`, `choices`, `state_changes`, `memory_entry` сохраняется.
2. Расширение — только через содержание `narration`, не через новые обязательные поля.
3. Опциональные поля (например, `mood`, `atmosphere`) допустимы с fallback для старых ответов.

### 4.3 Memory и контекст

1. Более богатый `narration` автоматически попадает в `activeSituation` и `recentTurns` через существующий `CampaignMemoryManager`.
2. `_compact()` и лимиты символов остаются; переполнение не должно ломать контекст.

## 5. Нефункциональные требования

- **Производительность:** Длина narration ограничена в промпте; fast mode использует краткий формат.
- **Локализация:** Промпты и любой новый UX — ru и en.
- **Надёжность:** Невалидный или укороченный ответ не ломает state; fallback на существующую логику.
- **Совместимость:** Старые save и старые ответы AI продолжают работать без миграций.

## 6. Definition of Done

1. System prompt содержит явные инструкции по narrative depth (атмосфера, эмоции, диалоги, сенсорные детали) на ru и en.
2. Игровой цикл проходит без регрессий; `flutter analyze` и `flutter test` проходят.
3. Пример сцены с диалогом и эмоциями воспроизводится в ручном тесте.
4. Fast mode по-прежнему возвращает краткий narration; JSON-контракт не нарушен.
