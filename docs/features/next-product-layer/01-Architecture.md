## 2. Цель этапа

Определить, где живёт фича Narrative depth, какие слои затрагивает, какие контракты меняются и какие риски появляются.

## 3. Выбор product direction

**Выбрано:** Narrative depth

**Альтернативы:**

| Направление      | Плюсы                          | Минусы                                      |
|------------------|--------------------------------|---------------------------------------------|
| Narrative depth  | Усиливает core value, мало изменений state | Зависит от качества промптов и модели       |
| Game systems     | Классические RPG-механики      | Тяжёлые миграции, сложный state engine      |
| Content slice    | Быстрое разнообразие           | Меньше архитектурной ценности               |

**Обоснование Narrative depth:** Проект — narrative RPG; AI генерирует повествование. Углубление нарратива — естественный следующий шаг. Memory layer уже готов; AI contract можно расширить без ломки детерминизма.

## 4. Вопросы архитектора

### Где в текущей архитектуре должна жить фича?

- **AI Gateway / OpenAI-compatible client** — расширение промптов и, при необходимости, структуры ответа.
- **Campaign Memory Manager** — использование новых полей (если появятся) для summary и context.
- **Game Engine** — без изменений; state_changes остаётся детерминированным.
- **Chat Screen** — отображение более богатого narration (эмоции, атмосфера, диалоги).

### Какие модели, репозитории, сервисы и экраны будут затронуты?

| Компонент                    | Изменения                                              |
|-----------------------------|--------------------------------------------------------|
| `TurnResult`                | Опционально: `mood`, `atmosphere`, `dialogue` — если решим структурировать |
| `openai_compatible_ai_client.dart` | Расширение system/user prompts для narrative depth   |
| `campaign_memory_manager.dart`     | Использование новых полей в context (если есть)       |
| `chat_screen.dart`         | Визуальное выделение диалогов/эмоций (опционально)    |
| Локализация                 | Новые строки для UI (если появятся новые элементы)     |

### Нужны ли миграции данных или изменения save/load?

**Нет.** Narrative depth реализуется через промпты и, при необходимости, расширение `TurnResult`. Существующие save совместимы: новые поля — опциональные с fallback.

### Как фича повлияет на AI-контракты, memory, локализацию и UX?

- **AI-контракт:** Промпты дополняются инструкциями по атмосфере, эмоциям, диалогам. JSON-схема может остаться прежней (narration как текст) или получить опциональные подполя.
- **Memory:** `narration` уже попадает в `activeSituation` и `recentTurns`. Более богатый narration улучшит контекст без изменения структуры.
- **Локализация:** Промпты уже локализованы (ru/en). Новые UI-элементы — ru/en.
- **UX:** Более выразительные сцены и диалоги в чате; при желании — визуальные акценты (цитаты, настроение).

### Какие риски и trade-off есть у решения?

| Риск                    | Митигация                                              |
|-------------------------|--------------------------------------------------------|
| Увеличение токенов      | Ограничить длину narration в промпте; fast mode — краткий формат |
| Нестабильный JSON       | Сохранить fallback; не добавлять обязательные поля     |
| Разный стиль у моделей  | Чёткие инструкции в промпте; примеры (few-shot) при необходимости |

## 5. Результат

### Архитектурное решение

1. **Фаза 1 (минимальная):** Расширить system prompt инструкциями по narrative depth:
   - атмосфера сцены
   - эмоции персонажей
   - короткие диалоги в narration
   - сенсорные детали (звук, запах, тактильность)

2. **Фаза 2 (опционально):** Добавить в `TurnResult` опциональные поля `mood`, `atmosphere` для UI-акцентов. Fallback — пустая строка.

3. **Граница:** Не меняем `state_changes` и детерминированную логику движка. LLM по-прежнему не источник истины для state.

### Затронутые файлы и модули

- `lib/src/core/services/openai_compatible_ai_client.dart` — промпты
- `lib/src/core/models/campaign_models.dart` — опционально TurnResult
- `lib/src/core/services/campaign_memory_manager.dart` — опционально использование новых полей
- `lib/src/features/chat/presentation/chat_screen.dart` — опционально визуальные акценты
- `lib/l10n/*` — при появлении новых UI-строк

### Риски

- Зависимость от качества модели: слабые модели могут игнорировать инструкции.
- Рост latency при длинном narration: мониторинг и ограничения в промпте.

### Границы этапа реализации

- Реализация ограничена промпт-слоем и, при необходимости, лёгким расширением TurnResult.
- Game systems, инвентарь, квесты — вне scope этого слоя.
- Content slice (новые сеттинги) — отдельная фича.
