# PRD: docs-encoding-sync

## 1. Контекст

Этап связан с [ImplementationPlan.md](D:/AI_PRG/ImplementationPlan.md) и нужен для того, чтобы команда могла безопасно продолжать работу по feature-пакетам без потери контекста.

## 2. Цель пользователя

Как владелец проекта, я хочу читать и использовать проектные документы без битой кодировки и рассинхрона с кодом, чтобы архитектор, аналитик, разработчик и тестировщик работали по актуальному контексту.

## 3. Пользовательские сценарии

1. Архитектор открывает `PRD.md` и `Architecture.md` и видит читаемый, актуальный контекст.
2. Аналитик открывает SpecKit memory-файлы и понимает реальные правила проекта.
3. Разработчик создает новую фичу по шаблону и не получает битые документы в feature-пакете.

## 4. Функциональные требования

1. Ключевые проектные документы должны быть переписаны в чистом UTF-8.
2. Документы должны соответствовать текущему состоянию MVP и post-MVP плана.
3. Workflow фич, git-веток и merge в `master` должен быть явно зафиксирован.
4. Feature templates и workflow docs должны быть читаемыми и пригодными для повторного использования.

## 5. Нефункциональные требования

1. Изменения не должны ломать ссылки между документами.
2. Документы должны оставаться краткими и практичными.
3. Обновленный контекст должен быть пригоден для автономной работы агента по pipeline.

## 6. Definition of Done

1. `PRD.md` читаем и отражает текущее состояние MVP.
2. `.specify/memory/project-context.md` читаем и согласован с правилами проекта.
3. SpecKit memory и feature workflow документы не содержат битой кодировки в ключевых местах.
4. `ImplementationPlan.md` и `docs/features/CATALOG.md` отражают актуальный статус этапов.
