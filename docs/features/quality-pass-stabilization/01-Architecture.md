# Architecture Plan: quality-pass-stabilization

## Контекст

После завершения локализации, fast mode и summary-memory проект функционально работает, но `flutter analyze` все еще шумный, а часть user flow покрыта проверками слабо.

## Цель этапа

Сделать первый безопасный engineering pass без смены продуктового поведения: уменьшить шум, укрепить тесты и зафиксировать стабильные сценарии.

## Архитектурное решение

1. Разбить стабилизацию на безопасные срезы:
   - lint cleanup для high-signal проблем
   - smoke/widget tests для ключевых экранов
   - проверка основных user flow
2. Не смешивать большой stylistic refactor и продуктовые изменения.
3. В первую волну брать только такие правки, которые:
   - не меняют игровой контракт
   - легко проверяются
   - уменьшают риск регрессий

## Основные проблемные зоны

1. `use_build_context_synchronously`
2. `avoid_types_on_closure_parameters`
3. `prefer_expression_function_bodies`
4. повторяющиеся style/info в моделях и экранах
5. нехватка coverage вокруг `New Game`, `Settings`, `Chat`

## Риски

1. Массовая stylistic чистка может размазать diff и усложнить review.
2. Можно потратить много времени на lint noise без реального product value.
3. Можно незаметно изменить поведение UI при механическом рефакторинге.

## Границы

В рамках первого прохода:

- чистим high-signal lint issues
- добавляем базовые smoke/widget tests
- валидируем ключевые сценарии MVP

Не делаем:

- большой архитектурный рефакторинг
- новую продуктовую функциональность
