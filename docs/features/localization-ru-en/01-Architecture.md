## 2. Проблема текущего состояния

Сейчас проект фактически одноязычный:
- строки UI лежат прямо в виджетах
- системные сообщения и fallback тоже зашиты в код
- AI prompt жестко ориентирован на русский
- нет единой точки выбора текущего языка приложения

Это мешает:
- поддерживать `ru/en` как продуктовый инвариант
- проверять completeness новой фичи
- переводить UI и AI-слой синхронно

## 3. Цель архитектуры

Построить минимальную, но системную локализацию, которая:
- задает язык приложения глобально
- выносит пользовательские строки из экранов и сервисов
- переключает весь UX между `ru` и `en`
- синхронизирует язык UI и язык AI prompt

## 4. Архитектурное решение

### 4.1 Единый localization layer

Нужен единый слой локализации, а не разрозненные строки по экранам.

Минимальная архитектура:
- `AppLanguage` enum: `ru`, `en`
- `AppLocalizations` или аналогичный lightweight wrapper
- централизованный словарь строк для UI
- текущий язык хранится в настройках приложения

### 4.2 Где хранить язык

Язык должен быть частью пользовательских настроек, рядом с AI settings.

Это позволит:
- сохранять выбранный язык между сессиями
- менять язык без отдельной временной логики
- использовать текущий язык как вход в AI-layer

### 4.3 Граница между UI и AI

Выбранный язык должен влиять на два слоя:

1. UI layer
- заголовки
- кнопки
- подсказки
- системные статусы

2. AI layer
- system prompt
- язык narration
- язык choices
- язык fallback/system messages

### 4.4 Что нельзя делать

Нельзя:
- оставить часть строк в виджетах
- сделать UI bilingual, а AI only-ru
- дублировать переводы по разным файлам без единого access layer

## 5. Изменения в данных и сервисах

### 5.1 Настройки

Нужно расширить модель пользовательских настроек:
- добавить `appLanguage`

### 5.2 App bootstrap

`MaterialApp` должен получать текущую локаль из application settings, а не быть жестко привязан к одному языку.

### 5.3 AI client

AI client должен строить prompt в зависимости от `AppLanguage`.

Минимально:
- `ru` -> ответ только на русском
- `en` -> ответ только на английском

## 6. Этапы внедрения

### Шаг 1
Добавить `AppLanguage` и хранение языка в настройках.

### Шаг 2
Вынести UI-строки в localization layer.

### Шаг 3
Добавить переключатель языка в приложение.

### Шаг 4
Подключить язык к AI prompt и fallback сообщениям.

### Шаг 5
Проверить все ключевые экраны и игровые сценарии на двух языках.

## 7. Риски

### Риск 1. Частичная локализация

Если часть строк останется в коде, приложение станет визуально смешанным.

### Риск 2. UI и AI расходятся по языку

Если язык UI хранится отдельно от AI prompt, пользователь получит смешанный опыт.

### Риск 3. Рост технического шума

Если локализация будет внедрена без единой архитектуры, дальше каждая новая фича будет добавлять новые hardcoded строки.

## 8. Границы реализации

Входит:
- `ru/en`
- UI
- статусы
- ошибки
- fallback тексты
- AI prompt

Не входит:
- третий язык
- внешняя система переводов
- cloud translation pipeline

## 9. Архитектурное решение

Рекомендуется:
- завести отдельный localization layer
- хранить `AppLanguage` в настройках
- переключать язык глобально через app scope
- пробрасывать выбранный язык в AI-layer

Это минимальный, но правильный путь для первого post-MVP этапа.
