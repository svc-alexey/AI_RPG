# PRD: Localization RU/EN

## 1. Контекст

Фича развивает обязательное требование проекта:
- приложение по умолчанию работает на русском
- приложение обязано поддерживать два полных языковых состояния: `ru` и `en`

## 2. Проблема пользователя

Сейчас пользователь не может полноценно переключать язык приложения.
Даже если часть UI будет переведена, без системного подхода останутся:
- русские системные сообщения
- русские fallback-ответы
- AI prompt, жестко привязанный к одному языку

## 3. Цель пользователя

Как пользователь, я хочу:
- использовать приложение на русском по умолчанию
- переключать его полностью на английский
- получать не только переведенный UI, но и AI-ответы на выбранном языке

## 4. Пользовательские сценарии

### Сценарий 1. Запуск по умолчанию
Новый пользователь открывает приложение.
Интерфейс и стартовые сценарии отображаются на русском.

### Сценарий 2. Переключение на английский
Пользователь открывает настройки и меняет язык на английский.
Весь UI, системные сообщения и AI-ответы переключаются на английский.

### Сценарий 3. Смена языка и продолжение кампании
Пользователь уже играет в кампанию, затем меняет язык.
Интерфейс и дальнейшие ответы AI должны использовать новый язык без поломки кампании.

### Сценарий 4. Demo/fallback режим
Если модель не настроена или ответ AI невалиден, fallback сообщения должны показываться на текущем языке приложения.

## 5. Функциональные требования

1. Система должна поддерживать два языковых состояния: `ru` и `en`.
2. Язык по умолчанию должен быть `ru`.
3. Пользователь должен иметь возможность переключать язык в настройках.
4. Все пользовательские строки UI должны браться из централизованного localization layer.
5. Системные статусы, ошибки и fallback сообщения должны переводиться через тот же layer.
6. AI prompt должен учитывать выбранный язык.
7. AI narration и choices должны запрашиваться на выбранном языке.
8. Выбранный язык должен сохраняться между сессиями.

## 6. Нефункциональные требования

1. Новая фича не считается завершенной, если реализована только для одного языка.
2. Переключение языка не должно требовать ручной перезагрузки приложения.
3. Решение должно быть расширяемым для новых экранов без возврата к hardcoded строкам.

## 7. Ограничения

1. В первый этап не входит поддержка третьего языка.
2. В первый этап не входит внешняя i18n-платформа.
3. Уже существующие сохранения кампаний не должны ломаться из-за добавления языка.

## 8. Definition of Done

1. `ru` и `en` работают как два полноценных режима приложения.
2. Приложение стартует на русском по умолчанию.
3. Все ключевые экраны переключаются между языками корректно.
4. Системные сообщения и fallback переводятся.
5. AI prompt и AI output следуют выбранному языку.
6. Выбранный язык сохраняется между сессиями.

## 9. Риски

1. Часть строк может остаться хардкоженной.
2. UI может переключаться, а AI нет.
3. Модель может иногда вернуть неверный язык, если prompt будет недостаточно жестким.

## 10. Открытые вопросы для реализации

1. Использовать встроенный Flutter localization pipeline или lightweight внутренний layer для MVP+?
2. Нужно ли мгновенно перерисовывать текущий чат при смене языка, или только новые системные сообщения и следующие AI-ответы должны быть на новом языке?
