# PRD: Платформа AI RPG (MVP -> V1)

## 1. Обзор продукта
**Название продукта:** AI RPG Platform  
**Тип:** Кроссплатформенная нарративная RPG с AI-генерацией и детерминированным движком состояния игры  
**Платформы:** Desktop (сначала), Android, iOS, Web (позже)  
**Клиентский стек:** Flutter  
**Ключевой принцип:** LLM генерирует повествование и предложения, но источником истины остается состояние игрового движка.

## 2. Цели и не-цели
### Цели (MVP)
1. Дать игроку выбор сеттинга, режима и сложности.
2. Дать создание игрового персонажа (шаблон/кастом/ручной).
3. Реализовать цикл игры: `сцена -> действие игрока -> ответ AI -> валидированное обновление состояния`.
4. Сохранять состояние кампании и память истории между сессиями.
5. Поддержать минимум 2 режима AI: OpenAI-compatible и локальный LM Studio.

### Не-цели (MVP)
1. Полноценный мультиплеер.
2. Полностью автономный конвейер генерации карт-изображений.
3. Сложная мета-экономика между кампаниями.
4. Обязательная полная RAG-инфраструктура.

## 3. Целевая аудитория
1. Казуальные игроки (сессии 10-20 минут).
2. Core RPG игроки (длинные кампании, более жесткие правила).
3. AI-энтузиасты и разработчики (локальные модели через LM Studio, кастомные endpoints).

## 4. Основные пользовательские сценарии
1. Игрок запускает короткое фэнтези-приключение с сгенерированным персонажем.
2. Игрок вводит действия в свободной форме и при желании запрашивает варианты действий.
3. Игрок сохраняет кампанию, закрывает приложение и позже продолжает с сохранением связности истории.
4. Продвинутый пользователь настраивает провайдера/base URL/модель/API key.

## 5. Функциональные требования
### 5.1 Настройка игры
1. Выбор сеттинга: `fantasy | detective | sci_fi`.
2. Выбор режима: `short_story | long_campaign`.
3. Выбор сложности: `easy | medium | hardcore`.
4. Режимы создания персонажа:
   - `template`
   - `partial_custom`
   - `manual`

### 5.2 Игровой цикл
1. Собирать контекст сцены из слоев памяти.
2. Отправлять структурированный запрос AI-провайдеру со строгим контрактом ответа.
3. Получать поля ответа:
   - `narration`
   - `state_changes`
   - `quest_updates`
   - `inventory_changes`
   - `choices`
   - `memory_candidates`
4. Валидировать изменения состояния по правилам движка.
5. Фиксировать новое состояние и добавлять лог хода.

### 5.3 Состояние и системы
1. Атрибуты и ресурсы персонажа (HP, энергия/мана, статусы).
2. Инвентарь с ограничениями по стакам и редкости.
3. Журнал квестов со статусами целей.
4. Флаги мира и отношения фракций.
5. Текущая локация и ограничения перемещения.
6. Логика поражения/смерти/permadeath (в зависимости от сложности).

### 5.4 Система памяти
1. Полный лог ходов.
2. Скользящие summaries кампании каждые N ходов.
3. Снимок канона мира (редкие обновления).
4. Карточки сущностей (NPC, предмет, локация, фракция, квест).
5. Retrieval-слой необязателен для MVP, запланирован для V1+.

### 5.5 Конфигурация AI
1. Выбор провайдера:
   - `built_in`
   - `openai_compatible`
   - `anthropic` (адаптер V1+)
   - `gemini` (адаптер V1+)
   - `lm_studio`
   - `custom`
2. Поля конфигурации: base URL, модель, API key/токен пользователя, timeout, размер контекста.
3. Проверка доступности провайдера из UI настроек.

### 5.6 Сохранение/загрузка
1. Локальные слоты сохранений.
2. Метаданные сохранений (название кампании, сеттинг, время последней игры, число ходов).
3. Экспорт/импорт JSON кампании (V1).
4. Облачная синхронизация на фазе premium/backend.

## 6. Нефункциональные требования
1. Детерминированная валидация AI-дельт до применения.
2. Целевой P95 latency обработки хода (desktop MVP): <= 6 сек (без учета вариативности удаленной модели).
3. Устойчивые к сбоям сохранения с версионированием схем.
4. Поддержка офлайн-режима с LM Studio.
5. Телеметрия токенов и стоимости (если включена).

## 7. Контракт AI-ответа
1. AI возвращает только строгий JSON.
2. Движок игнорирует неизвестные ключи.
3. Движок отклоняет некорректные state deltas.
4. Промпты и схема ответа AI должны быть версионированы.

## 8. Экономика и монетизация (V1+)
1. Бесплатный слой:
   - ограниченные сохранения
   - короткие истории
   - дневные лимиты генерации
   - пресетные изображения
   - базовые модели
2. Premium:
   - длинные кампании
   - повышенные лимиты
   - облачные сохранения
   - расширенные summaries/глубина памяти
   - premium-функции картинок и карт
3. Мобильные покупки:
   - Google Play Billing
   - Apple StoreKit (IAP)

## 9. Метрики (критерии успеха)
1. D1 retention >= 30% (цель).
2. Доля завершенных коротких историй >= 40%.
3. Успешность save-resume >= 99%.
4. Доля отклоненных невалидных AI-дельт < 5% после настройки промптов.
5. Средняя стоимость хода укладывается в бюджет (по режиму провайдера).

## 10. Риски и меры
1. **Потеря связности нарратива на длинных сессиях** -> слоистая память + summaries.
2. **Галлюцинации AI, нарушающие правила** -> детерминированный валидатор.
3. **Скачки стоимости** -> телеметрия токенов + политика компрессии summaries.
4. **Зависимость от одного провайдера** -> единые адаптеры AI gateway.
5. **Небезопасный контент** -> модерация и настраиваемые guardrails.

## 11. План релиза
### Фаза 1: Desktop MVP
1. Один сеттинг, короткая история, создание персонажа.
2. Адаптеры OpenAI-compatible + LM Studio.
3. Save/load, summaries, валидатор.

### Фаза 2: Расширение движка
1. Доработка квестов/фракций/флагов мира.
2. Дополнительные адаптеры провайдеров.
3. Built-in backend режим.

### Фаза 3: Мобильный запуск
1. Сначала Android, затем iOS.
2. Entitlements и биллинг.
3. Облачные сохранения + premium-ограничения.

## 12. Критерии приемки (Definition of Done для MVP)
1. Новый игрок может пройти полный цикл короткой кампании от старта до финала.
2. Ответ AI всегда парсится в структурированный формат или безопасно обрабатывается fallback-логикой.
3. Save/load восстанавливает полностью игровое состояние без ручной коррекции.
4. Уровни сложности заметно меняют правила и исходы.
5. Локальный режим LM Studio работает через настраиваемый endpoint.
