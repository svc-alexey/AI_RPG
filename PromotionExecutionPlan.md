# Promotion Execution Plan

## Цель

Превратить общий промо-замысел из `promotion_ai_rpg.md` в последовательный, управляемый запуск без рекламного бюджета.

## Принцип запуска

Промо-кампания запускается не сразу по всем каналам, а волнами:

1. сначала готовим базу
2. затем запускаем регулярный контент
3. потом приводим первых тестеров
4. после этого усиливаем только те форматы, которые реально сработали

## Этап 0. База перед запуском

Цель: подготовить минимальный фундамент, без которого промо будет распадаться.

Чекбоксы:

- [ ] Зафиксировать одно основное позиционирование проекта
- [ ] Подготовить короткое описание проекта на `ru`
- [ ] Подготовить короткое описание проекта на `en`
- [ ] Подготовить 5-7 скриншотов или визуальных сцен из игры
- [ ] Подготовить 3-5 сильных примеров прохождений
- [ ] Подготовить короткий CTA для набора тестеров
- [ ] Определить один основной канал для `ru`
- [ ] Определить один основной канал для `en`

Артефакты этапа:

- один master pitch
- один short pitch
- набор скриншотов
- набор игровых историй
- текст приглашения в тестирование

Готовность к следующему этапу:

- [ ] Есть готовый пакет материалов, который можно публиковать без срочной доработки

## Этап 1. Контентовый цикл

Цель: начать регулярную публикацию без перегруза команды.

Рекомендуемая частота:

- 2 поста в неделю для основного канала
- 1 короткий клип или короткий фрагмент в неделю

Чекбоксы:

- [ ] Выбрать 3 контент-рубрики для первых 3 недель
- [ ] Составить контент-план на 2 недели вперед
- [ ] Подготовить шаблон devlog-поста
- [ ] Подготовить шаблон поста с игровой сценой
- [ ] Подготовить шаблон поста с фейлом или неожиданной развилкой
- [ ] Назначить единый формат хранения контент-идей
- [ ] Назначить единый формат хранения лучших историй игроков

Рекомендуемые рубрики:

- devlog
- сцена из прохождения
- сравнение моделей
- смешной фейл
- голосование за следующий сеттинг

Готовность к следующему этапу:

- [ ] Есть контент минимум на 2 недели вперед

## Этап 2. Первый набор тестеров

Цель: привести первых людей не ради охватов, а ради фидбека и историй.

Чекбоксы:

- [ ] Сформулировать, кто именно нужен как первый тестер
- [ ] Определить, куда именно их звать
- [ ] Подготовить сообщение-приглашение для `ru`
- [ ] Подготовить сообщение-приглашение для `en`
- [ ] Подготовить короткую форму сбора фидбека
- [ ] Подготовить список вопросов для первого интервью или опроса
- [ ] Определить, как сохранять лучшие цитаты и лучшие истории игроков

Что собирать с первых тестеров:

- что было самым сильным моментом
- где стало скучно
- где ход ощущался медленным
- насколько понятен был state и memory
- захотелось ли продолжить кампанию

Готовность к следующему этапу:

- [ ] Есть первые 5-10 тестеров
- [ ] Есть первые отзывы, которые можно превращать в контент

## Этап 3. Пилот по каналам

Цель: не распыляться, а проверить, какие каналы реально дают отклик.

Чекбоксы:

- [ ] Запустить `Telegram` как основной `ru` канал
- [ ] Запустить `Reddit` как основной `en` канал
- [ ] Запустить один короткий видео-канал
- [ ] Сделать минимум 3 публикации в Telegram
- [ ] Сделать минимум 2 публикации на Reddit
- [ ] Сделать минимум 2 коротких видео
- [ ] Зафиксировать отклик по каждому формату

Что считать откликом:

- комментарии
- личные сообщения
- переходы в тестирование
- сохранения постов
- повторные реакции от тех же людей

Готовность к следующему этапу:

- [ ] Понятно, какой канал и какой формат дают лучший сигнал

## Этап 4. Усиление того, что сработало

Цель: масштабировать не все подряд, а только рабочие форматы.

Чекбоксы:

- [ ] Выбрать 1 основной канал роста
- [ ] Выбрать 1 резервный канал роста
- [ ] Выбрать 2 лучших формата контента
- [ ] Увеличить частоту публикаций только в рабочих форматах
- [ ] Ввести еженедельную подборку лучших историй игроков
- [ ] Ввести еженедельный мини-devlog
- [ ] Собирать повторяющиеся вопросы пользователей в отдельный список

Результат этапа:

- появляется повторяемый промо-цикл
- контент начинает производиться из самой игры и фидбека
- набор тестеров становится постоянным, а не разовым

## Минимальный запуск без перегруза

Если делать совсем бережно, то стартовый порядок такой:

1. подготовить позиционирование и 5 сильных материалов
2. открыть Telegram или другой основной `ru` канал
3. открыть Reddit как основной `en` канал
4. начать публиковать 2 поста в неделю
5. отдельно собирать лучшие сцены и фейлы
6. через 2 недели посмотреть, что реально цепляет людей

## KPI первого месяца

Не гнаться за vanity metrics. На первом месяце важнее такие сигналы:

- [ ] 10 первых тестеров
- [ ] 3-5 содержательных отзывов
- [ ] 10+ сохраненных контент-идей
- [ ] 5+ сильных игровых историй для публикации
- [ ] 1-2 формата, которые реально вызывают обсуждение

## Что делать не надо на старте

- [ ] Не пытаться одновременно вести слишком много каналов
- [ ] Не делать ставку только на “официальные объявления”
- [ ] Не публиковать сухие описания без конкретных игровых сцен
- [ ] Не звать массово людей до появления базового контент-потока
- [ ] Не масштабировать канал, если с него нет фидбека или тестеров

## Следующий практический шаг

Самый правильный следующий шаг:

- [ ] На основе этого плана подготовить `PromotionBacklog.md` с конкретными задачами на ближайшие 2 недели
